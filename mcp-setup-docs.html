Figma + Claude Setup

What you need

  • Claude Desktop app installed
  • Figma account (Dev seat recommended, ~$10–12/month, gets 200 calls/day instead of 6–20/month on Starter)
  • Make sure you're actually added to the client's file/team, not just signed in

Steps

  1. Open Claude Desktop → Settings → Connectors
  2. Click Add custom connector
  3. Paste URL: https://mcp.figma.com/mcp
  4. Click Add, then sign in with your Figma account when prompted
  5. Confirm it shows Connected

To use it

  1. In Figma, right-click the frame you want → Copy link to selection (not a plain file link)
  2. Paste that link to Claude
  3. Say what you want (build this, describe this, extract colors, etc.)

Notes

  • Reading counts against your monthly limit, writing/editing is free during Figma's beta for now
  • No Figma desktop app needs to stay open
  • Skip third-party "unlimited" Figma MCP plugins for client work — personal projects only

Added under

Claude Code CLI (terminal), not Claude Desktop chat. Desktop's Connectors UI doesn't support this (OAuth only); Claude Code does, via custom header auth.

Simple steps (Elementor's built-in prompt)

  1. WP Dashboard > Elementor > Elementor MCP panel
  2. Make sure the Claude Code tab is selected (also has Claude Desktop, Codex, Cursor, Other)
  3. Click Copy prompt — this copies a ready-made connection block, including the app password, for that site
  4. Open Terminal, run claude to start a session
  5. Paste the copied prompt and send it — Claude Code sets up the connection itself

Verify connection

claude mcp list

Confirm: [server-name] ... Connected

Manual route (if needed) The MCP panel also has a "Prefer manual configuration?" link, which gives the raw JSON block (server name, URL, Basic auth header) to add yourself via claude mcp add --transport http [server-name] "[mcp-url]" --header "Authorization: Basic [base64-string]". Use this only if the Copy Prompt route doesn't work.

Use it

claude

Opens a terminal chat session with the tools below loaded.

What it can do

Look at things

  • List pages and posts
  • Read a page's structure
  • List media files (list-assets)
  • List reusable components (list-components)
  • List header/footer parts (list-site-parts)
  • List/read widget types (list-widget-schemas, get-widget-schema)
  • Read site resources (list-resources, read-resource)
  • Read default styles (get-default-styles)

Make things

  • Create new page (create-page)
  • Build full layout in one go (build-composition)
  • Create a component (manage-component)
  • Create header/footer part (manage-site-parts)

Change things

  • Add/edit/move/delete elements (manage-elements)
  • Change page settings (update-page-settings)
  • Manage CSS classes (manage-classes, reorder-classes)
  • Manage global variables, colors and fonts (manage-global-variable)
  • Change default styles (manage-default-styles)

Ship things

  • Publish (publish-document)
  • Create preview link before publishing (create-preview-link)

Not available for either type (v3 or v4)

  • Save as template
  • Insert a template
  • Duplicate a whole page

Does v3 vs v4 change the design look?

Same

  • The look: colors, fonts, spacing and layout can all be matched in v4
  • Page content: headings, text, buttons, images and links
  • Responsive behavior: v4 supports mobile and tablet breakpoints
  • Publishing: the page works the same on the front end

Different

  • How styling is stored — v3 uses panel settings + custom CSS, v4 uses plain CSS per element, global classes and global variables
  • Editor panels — controls sit in different places, some v3 options have no v4 equivalent
  • Widgets — some v3-only widgets (Lottie, text slider, accordion, etc.) don't have a direct v4 match
  • Shared parts — existing global templates stay as v3 and don't auto-convert
  • Global styles — if the site has no global variables/classes yet, a v4 build uses fixed colors/sizes chosen manually

What this means in practice

  • Original v3 design settings can't be read by the MCP — exact fonts, colors, sizes and spacing can't be copied automatically
  • A v4 rebuild matches structure and wording; styling gets picked manually or matched from a screenshot
  • Expect a close match, not pixel-identical — do a visual check after rebuilding
  • If an identical look matters most, keep the v3 version and edit text by hand instead of rebuilding

Limitations hit so far, and the fix for each

#ProblemWhat to do
1 Old v3 elements and v3 templates — MCP can read their structure but not their text or styling. Edit text by hand in Elementor. Or rebuild the page in v4 (see #4).
2 MCP can't edit v3 elements. A heading edit returned elementor_v3_not_supported. Same as #1. Only v4 elements can be changed through the MCP.
3 No tool to save a page as a template, insert a template, or duplicate a page. Do it in WordPress. Save as Template, then Add Template → My Templates → Insert.
4 A v4 rebuild needs the original wording, and the MCP can't read it from v3. Paste the page text to Claude directly. Or approve the live-page fetch if it's blocked.
5 Atomic Editor was off, so every build call failed. Turn it on: WP Admin → Elementor → Settings → Features.
6 MCP reconnected only after re-adding it. Restart Claude Code, or run /mcp if the tools go missing.
Scope Works only inside Claude Code CLI sessions (terminal: claude). Not available in Claude Desktop chat window or claude.ai web chat — those use a separate, OAuth-only connector system.
